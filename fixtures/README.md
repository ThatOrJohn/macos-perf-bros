# Fixtures

Raw captures of every data source, used to build and test the collectors and parsers. They're generated by [`scripts/capture-fixtures.sh`](../scripts/capture-fixtures.sh), and each capture goes in its own folder: `raw/<chip>_macos-<version>/`.

| Capture | Machine | Notes |
|---|---|---|
| `raw/apple-m1_macos-27.0.1/` | Mac mini (Macmini9,1), M1, 4E+4P, 16 GB, no battery | Captured 2026-11-23. Heavy swap in use at the time (14.1 of 15 GB). |

## Files per capture

| File | Contents |
|---|---|
| `powermetrics/idle-all.plist` | `--samplers all`, 5 samples at 1 s. Used to discover which keys exist. |
| `powermetrics/idle-app.plist` | The sampler set the app will use, at idle, 5 samples. |
| `powermetrics/cpu-load-app.plist` | The same set with every core saturated by `yes`, 5 samples. |
| `powermetrics/idle-all.txt` | Text format, 2 samples, as a human-readable reference. |
| `unprivileged/*` | `sysctl` (topology and runtime), `vm_stat`, `memory_pressure -Q`, `pmset -g batt`, `nettop -P` (per process, 2 samples), `ps` top 40. |

## powermetrics plist: findings that shape the parser

The output is a stream of XML plists separated by **NUL** (`\0`). Each one is a single sample. Every sample has `is_delta = true` and `elapsed_ns` around 1.02 s, so **use `elapsed_ns`, not the nominal interval**, when computing rates yourself.

### Paths to use

| Snapshot field | Plist path | Unit and notes |
|---|---|---|
| clusters | `processor.clusters[]` | `name` is `"E-Cluster"` or `"P-Cluster"`. Classify by prefix. |
| cluster freq | `clusters[].freq_hz` | **Hz** |
| cluster max freq | `clusters[].dvfm_states[-1].freq` | **MHz**. M1: E = 2064, P = 3204. |
| cluster active | `1 - clusters[].idle_ratio` | Cluster-level: active if *any* core is busy. This is **not** the average of the cores (idle: 0.57 vs. about 0.28 average). |
| core active | `1 - clusters[].cpus[].idle_ratio` | `cpus[].cpu` is the logical CPU id. On M1, ids 0–3 are E and 4–7 are P. |
| core freq | `clusters[].cpus[].freq_hz` | Hz |
| CPU / GPU / ANE power | `processor.cpu_power`, `gpu_power`, `ane_power` | **mW**. Package total = `combined_power`. |
| GPU freq | `gpu.freq_hz` | ⚠️ **actually MHz** despite the name (for example 713.6). |
| GPU max freq | `gpu.dvfm_states[-1].freq` | MHz (M1: 1278) |
| GPU active | `1 - gpu.idle_ratio` | |
| thermal | `thermal_pressure` | String: `"Nominal"` seen. Other values are assumed to be Moderate, Heavy, Trapping and Sleeping, but that's **unverified**. |
| net throughput | `network.ibyte_rate`, `obyte_rate` | bytes/s |
| disk throughput | `disk.rbytes_per_s`, `wbytes_per_s` | bytes/s, plus `rops_per_s` and `wops_per_s` |
| per-process | `tasks[]` | `pid`, `name`, `cputime_ms_per_s` (1000 = one full core), `energy_impact_per_s`, `idle_wakeups_per_s`, `diskio_*_per_s`, `bytes_*_per_s` |
| totals | `all_tasks` | The same fields, summed. It's a separate key and doesn't appear in `tasks[]`. |
| battery | `battery.percent_charge` | ⚠️ It's `0` on a Mac without a battery, not missing. Use `pmset -g batt` to decide whether a battery exists. |

### Gotchas

- **Filter pseudo-tasks.** `tasks[]` includes `DEAD_TASKS` (pid −1), which is often the #2 CPU consumer. Exclude it from Process Plains, or show it as a "ghost".
- **No per-process memory.** There's no RSS in `tasks[]`, so join it with `ps` (or later libproc) by pid.
- **No per-process GPU time.** `--show-process-energy` is documented to include `--show-process-gpu`, but no GPU field appears in the plist on this machine. That answers DESIGN §14: Process Plains can't show per-process GPU from powermetrics.
- **The `ane_power` sampler adds nothing** beyond `processor.ane_power` on M1. That may differ on newer chips.
- **Sample size is about 375 KB of XML**, mostly from `tasks[]`. Parse time at 1 Hz needs measuring in Bun. If it's too slow, drop the `qos_*` fields upstream or switch the tasks sampler to a slower cadence.
- powermetrics prints `Second underflow occured.` to **stderr** now and then. Ignore it, and don't treat stderr output as a failure.

### Not covered yet

- Thermal pressure other than Nominal, swap growing over time, GPU under load, and any machine with a battery. Use synthetic fixtures (phase 1) or a capture from another Mac.

## Synthetic replays

The checked-in [scenarios](scenarios/) use the bundled M1 capture as a seed and contain 20 snapshots at one-second intervals. Load peaks at playback times 9 and 10 seconds, then returns to its initial level. The degraded replay retains CPU busy percentages, memory, and processes while omitting privileged readings.

```sh
bun run scripts/make-scenarios.ts
bun run src/main.ts --replay fixtures/scenarios/cpu-fire.ndjson
bun run stills -- --scenarios
```

Scenario stills replay the ramp before capturing each scene at 10.5 seconds. Look in `docs/stills/scenarios/<scenario>/` for both the half-block and hi-res PNGs.

## Privacy

Captures are anonymized by [`scripts/anonymize-fixtures.py`](../scripts/anonymize-fixtures.py), which `capture-fixtures.sh` runs automatically:

- **Kept:** names of Apple/system executables, meaning anything running from `/System`, `/usr/libexec`, `/usr/bin`, `/usr/sbin`, `/bin`, `/sbin` or `/Library/Apple`, plus `kernel_task`, `launchd`, `DEAD_TASKS` and `yes`. The list is built from the live process table, so **anonymize on the capturing machine, right after capture.**
- **Replaced:** every other process name becomes `app-NN`, mapped consistently across all files in a capture. In `ps-top.txt`, third-party executable paths become just `app-NN`.
- **Users:** anything other than `root` and `_system` accounts becomes `user`.
- `nettop` runs per-process only (`-P`), so no remote hosts or addresses are recorded.

The script is idempotent. After anonymizing, PIDs, timings and all metric values are unchanged.
